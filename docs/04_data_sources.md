## 2. 링크 읽기

### 지켜야 할 것
- **기본은 메타 정보(`og:title`·`og:description`)만** 읽습니다(TRD). 본문 읽기는 평가·`/legacy` 전용 옵션입니다.
- **robots.txt 를 확인하고, 금지된 경로는 요청하지 않습니다.** 예: 카카오맵 장소 상세 JSON(`place.map.kakao.com/main/v/…`)은 robots.txt 가 막고 있어 요청이 거부됐습니다(이번 조사에서 직접 확인).
- 같은 호스트에 초당 1회 이하로 요청하고, 결과를 캐시합니다. 로그인·인증 우회는 하지 않습니다.
- 서비스 약관상 대량 수집은 금지일 수 있습니다. **사용자가 직접 저장한 링크 1건을 그때그때 읽는 용도**로만 씁니다.

### 출처별
| 출처 | 얻을 수 있는 것 | 상태 |
|---|---|---|
| 네이버 블로그 (`m.blog.naver.com`) | 제목·요약. 본문은 평가·`/legacy` 옵션에서만 | 구현됨 |
| 네이버 지도 링크 (`map.naver.com/.../place/{id}`) | place ID 만 (본문은 JS 렌더링) | v0.1 구현 |
| 네이버 플레이스 (`pcmap.place.naver.com/place/{id}/home`) | 서버 렌더링된 상태 JSON 의 이름·주소·좌표·카테고리, 있으면 영업시간·메뉴 | ⚠️ 내부 구조라 구조 미검증, 바뀔 수 있음. 상용 스크래퍼들도 영업시간·메뉴는 별도 "enrichment" 단계로 처리하고 실패를 허용함 [Apify](https://apify.com/khadinakbar/naver-map-scraper) |
| 네이버 지도 내부 API | 검색 결과 JSON | 헤더·쿠키를 흉내내야 동작한다는 사례 [인프런](https://www.inflearn.com/community/questions/435531/네이버-지도-크롤링-관련-질문) → **우회 성격이라 사용 안 함** |
| 카카오맵 장소 상세 | 영업시간·메뉴 JSON | **robots.txt 금지 → 사용 안 함** |
| 인스타그램 | OG 캡션 (차단될 수 있음) | 구현됨, 실패 시 캡쳐 요청 |

### 인스타그램 실측 (2026-11-04, 게시물 1건)
| 항목 | 결과 |
|---|---|
| 서버 일반 요청: 게시물 페이지 | 200, 캡션·표지 `og:image` 있음, 슬라이드 데이터 없음 |
| 서버 일반 요청: `og:image` 다운로드 | 성공 |
| 서버 일반 요청: 임베드 페이지 | 슬라이드 주소 0개 |
| 브라우저: 임베드 페이지 | 슬라이드 8장 전부 확인 |
| 모바일 브라우저: 게시물 페이지 | 2장째 이후 앱 유도 팝업, 이후 사진 로드 안 됨 |

- 서버에서 전체 슬라이드를 얻을 수 없어 현재 구현은 표지도 읽지 않습니다. 기기 안 WebView 수집은 실제 기기에서 시험하지 않았고, 자동 수집이라 약관 위험이 있습니다.
- `robots.txt`는 User-Agent마다 다르게 응답합니다. 기본 `curl`에는 `Disallow: /`, 모바일 User-Agent에는 자동 수집 금지 문구가 나옵니다. 코드는 PC용 User-Agent로 읽어 허용으로 판단합니다.

## 3. 캡쳐 읽기: OCR → 비전 LLM

### Tesseract (무료·로컬)
- 한국어 언어 데이터(`kor`)가 필요합니다. macOS: `brew install tesseract tesseract-lang`.
- **실측**: 사용자가 보낸 네이버 플레이스 홈 화면 캡쳐(753×2000)를 `kor+eng`, `--psm 4` 로 읽었을 때 정확도는 아래와 같았습니다.
  - 정확: 상호명, "일식당 · 4.88 · 리뷰 539", "17:00에 영업 시작", 주소(호수 "201호"→"2018" 오인식), 역·출구·거리, 전화(0507-…), 예약 링크(catchtable), 편의 줄
  - 깨짐: 사진 위 글자·아이콘 주변, 탭 이름 일부
  - → 플레이스 화면은 **줄 단위 규칙 파서**로 대부분 구조화 가능. 영업시간은 홈 탭에 "오늘 시작 시간"만 보이는 경우가 많아 **정보 탭(요일별 시간) 캡쳐를 같이 받는 흐름**이 필요합니다.

### 비전 LLM 폴백 (선택, 사용량 과금)
OCR + 규칙 기반으로 추출하지 못한 캡쳐만 비전 LLM으로 보냅니다. 조건은 [02_workflow.md](02_workflow.md)에 있습니다.

| 실측 (2026-11-04) | 결과 |
|---|---|
| 인스타 캡쳐 1장 (음식 사진 위 꾸민 글씨), Tesseract + 규칙 기반 | 주소만 읽고 상호명 누락, 장소 0개 |
| 같은 캡쳐, `gpt-4o-mini` 폴백 | 상호명·주소 추출, 카카오 후보 일치 |
| 인스타 캡쳐 30장, Tesseract + 규칙 기반 | 맞힌 장소 0곳 |
| 게시물 설명의 지역 이름, Tesseract | 캡션이 보이는 스크린샷 22장 중 21장에서 읽음 |
| 사진 속 주소, Tesseract | 27곳 중 2곳만 읽음 |
| 38건 평가 (이미지 30 · 링크 8), OCR+`gpt-4o-mini` | 이름 재현율 90%, 후보 연결 약 50%, 평균 약 9초, 최대 약 60초 |

정답은 사람이 확인하기 전 초안이고 혜화·잠실 게시물에 쏠려 있어, 일반적인 정확도로 볼 수 없습니다. 측정 도구는 [eval/real/README.md](../eval/real/README.md)에 있습니다.

## 4. 이동 시간 (무료·무키)
- 현재 추천은 **도보만** 씁니다: 직선거리(haversine) × 우회계수 1.3 ÷ 4.5km/h (`v3/walking.py`)
- 로컬 전용 `/legacy`의 `route.py`는 수단별 속도를 씁니다: 자전거 12km/h · 대중교통 18km/h + 대기 8분 · 자가용 22km/h + 주차 7분 (도심 기준 ⚠️ 추정치), 700m 이내는 도보
- 공개 경로 서버(OSRM 데모 등)는 이용 정책상 서비스 트래픽에 쓰기 어렵고, 대중교통 경로는 무료 무키 API 가 없음 → **추정치 + "추정" 라벨**, 실제 길찾기 연동은 인터페이스만 열어 둠.
