# 실제 데이터 평가

실제 캡쳐·링크로 세 방식을 같은 정답으로 비교합니다.

| 방식 | 내용 | LLM 호출 |
|---|---|---|
| `ocr` | Tesseract + 규칙 기반 | 없음 |
| `ocr_llm` | OCR로 추출하지 못한 캡쳐만 비전 LLM | 실패한 캡쳐만 |
| `llm` | 처음부터 LLM | 모든 케이스 |

## 데이터 위치
데이터는 저장소에 올리지 않습니다. 캡쳐에는 저작권이 있는 사진과 다른 사람의 계정명이 들어 있을 수 있습니다.
```
data/real_eval/
  cases.jsonl    정답 (형식은 cases.example.jsonl)
  images/        캡쳐 원본
  report.md      평가 결과 (실행 시 생성)
  results.json   케이스별 상세 (실행 시 생성)
```

## 정답 형식
`cases.jsonl`은 한 줄에 케이스 1건입니다.

| 필드 | 설명 |
|---|---|
| `id` | 중복 없는 이름 |
| `kind` | `image` · `link` · `text` |
| `input` | 이미지는 `data/real_eval/` 기준 경로, 그 외는 링크나 문구 |
| `note` | (선택) 함께 붙여넣은 캡션 |
| `segment` | 유형별 집계 이름 |
| `verified` | 사람이 정답을 확인했으면 `true` |
| `expected` | 있어야 할 장소 `[{name, address, area, aliases}]`. 장소가 없어야 하면 `[]`. `area`는 주소가 없을 때 쓰는 구 이름(예: `송파구`) |

`verified`가 `false`인 케이스가 있으면 리포트에 경고가 붙습니다. **정답은 원본을 보고 사람이 확정하세요.**

## 실행
```bash
python -m eval.real.run_real_eval --dry-run
python -m eval.real.run_real_eval --modes ocr
python -m eval.real.run_real_eval --provider openai --model gpt-4o-mini --max-llm-calls 30
```
- `ocr_llm`·`llm`은 캡쳐를 외부 LLM으로 보내고 요금이 나옵니다. 민감한 내용이 담긴 캡쳐는 빼세요.
- 기본으로 카카오 검색까지 실행합니다. `--no-search`로 끌 수 있고, 그러면 후보 연결 지표가 나오지 않습니다.
- 블로그 태그는 호출하지 않습니다.

## 지표
| 지표 | 뜻 |
|---|---|
| 이름 재현율 | 정답 장소 중 이름을 맞게 추출한 비율 |
| 이름 정밀도 | 추출한 장소 중 정답 비율 |
| 주소 정확도 | 이름을 맞힌 장소 중 도로명·건물번호까지 맞은 비율 |
| 후보 연결 | 정답 장소 중 기본 선택 후보로 올바른 장소가 나온 비율. 주소가 있으면 주소로, 없으면 이름과 `area`로 판정 |
| 잘못된 후보 | 기본 선택 후보 중 정답이 아닌 수. 사용자가 그대로 저장할 위험이 있어 가장 중요하게 봅니다 |
| 장소 없음 오탐 | 장소가 없어야 하는 케이스에서 무언가 추출한 건수 |

이름 일치는 공백·기호를 뺀 뒤 완전히 같거나 지점명만 더 붙은 경우입니다. 오독을 찾아내려고 일부러 엄격하게 잡았습니다. 표기가 여럿이면 `aliases`에 적으세요.
